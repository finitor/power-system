# 2026-06-19

## Charge allocation: simplify the knee policy

Afternoon traces showed the PV-power weighted allocator had a real latch. Once
the Classic was driven to `0 A`, its PV input power collapsed and it entered a
rest/float edge state. The allocator then interpreted that low PV power as low
available resource and kept assigning nearly the whole constrained budget to the
EPEver. A supervisor restart temporarily cleared the smoothed PV-power memory
and let the Classic recover, which made the failure mode pretty clear.

The allocator now uses an equal split across eligible charge controllers, with
the existing water-fill cap redistribution if one controller hits its configured
maximum. This is intentionally simpler than the PV-power experiment and better
matched to the current operating goal: keep both arrays participating near the
BMS knee without building a self-reinforcing control loop.

The allocator reserve default is now `0 A`. The upstream `ChargeCeiling` already
uses a conservative 50% fraction of the BMS CCL, so subtracting another fixed
`5 A` margin was starving useful charge. The measured-current feedback clamp
remains in place if net battery charge exceeds the resolved allowance.

The live stabilizer still holds small non-emergency changes, but equal-split
decisions can now rebalance stale unequal controller limits when the existing
spread is at least one deadband wide. This prevents old `10 A / 15 A` style
splits from persisting merely because both controllers are individually close to
the new raw equal target.

## Missing controller telemetry

The allocator already excluded a controller with missing telemetry from the
eligible set, so the remaining controller received the whole net allowance.
However, the load estimator required Classic telemetry specifically. If Classic
went offline while EPEver remained online, the allocator lost the household-load
allowance and under-allocated the remaining controller.

The instantaneous load balance now sums whichever charge-controller outputs are
available:

```text
load = known charge-controller output - BMS net battery current
```

So if Classic is absent and EPEver is carrying `4 A` while battery net current is
`0 A`, EPEver receives the full `20 A` knee allowance plus the `4 A` load
allowance. If a silent controller is secretly still producing, that hidden power
shows up through BMS net current: it reduces the inferred load allowance while
it is below household load, and only triggers the measured-current feedback
clamp if net battery charge rises above the resolved allowance.

Live verification after deployment showed the normal two-controller case at
about `20 A` net allowance, `24-25 A` budget including load, equal split, and
`12 A / 12 A` controller targets.
