# 2026-06-18 — EPEver charge coil anomaly and allocator sleep/release policy

Morning field observation: the Classic was already producing, but the EPEver was
stuck in `Resting / No charging` despite seeing high PV voltage. The operator
noted the Pi was `blueberry.local` / `.200`; any stale `.153` assumptions were
discarded before touching the live system.

## Immediate recovery

Direct EPEver register inspection showed the charge enable coil was OFF:

- `coil_0000_charge_enable False`
- PV voltage around 160 V
- battery around 53.1 V
- EPEver status `No charging`
- max charging current still 100 A

Enabled the coil through the supervisor API:

```sh
POST /api/v1/control/epever/charging {"enabled": true}
```

Within seconds the EPEver moved back to `Absorb (Boost)` and began producing.
Later live checks after supervisor restarts showed EPEver in Boost/Absorb at a
few amps with allocator target `disable=false`, `target_a=100.0`.

## What put it there

The metric event store was more useful than journald: successful coil changes
were not logged yet, but `charge_allocator` events recorded the allocator's
intent. The important transition was:

- `2026-06-17 21:52:53 EDT`: EPEver target `disable=true`,
  reason `charger inactive`.

Telemetry around that time showed the EPEver input collapsing toward the battery:

- `21:52`: PV 57.5 V, battery 53.0 V
- `21:53`: PV 54.2 V, battery 53.0 V
- `21:54`: PV 53.0 V, battery 53.0 V

So the allocator observed a low-input sunset condition and translated it into
the same actuator intent used for battery safety stops. That was the category
mistake: an EPEver going to sleep at dusk is a resource-side state, not a reason
for the supervisor to use the hard charge coil.

The morning recovery bug was separate but related. Once the EPEver current limit
was already at 100 A, allocator decisions that wanted it enabled often had
`should_write=false`. The actuator path only reconciled the EPEver coil when a
current-limit write was also pending, so a stale OFF coil could survive into the
morning even though the target said `disable=false`.

## Fixes

First fix, deployed immediately: reconcile the EPEver charge coil independently
from current-limit writes, and log successful coil transitions. After restart the
journal showed:

```text
Charge allocation: epever coil -> True
```

That made the supervisor recover a stale OFF coil on startup/current-limit
steady state.

Second fix, the actual policy correction: low-input / resting chargers now
release constraints instead of becoming disable targets.

- Inactive/unavailable charger target is now "release to max current limit" with
  `disable=false`.
- EPEver coil OFF is reserved for explicit battery/control-side stops:
  BMS charge disabled, CCL zero, full-charge latch, or cell-safety stops.
- Sub-floor eligible allocations still floor to the controller's minimum current
  rather than disabling.

Availability was changed from PV-voltage-based to controller-state-based because
field observation showed both PV strings can report >100 V in twilight while
there is no useful loaded power behind that voltage.

- Classic available stages: `Bulk`, `Absorb`, `Float`, `Equalize`.
- EPEver available stages: `Absorb (Boost)`, `Float`, `Equalize`.
- Classic `Resting` and EPEver `No charging` are debounced before release
  (`CHARGE_ALLOC_CLASSIC_SLEEP_DEBOUNCE_S`,
  `CHARGE_ALLOC_EPEVER_SLEEP_DEBOUNCE_S`, default 180 s).

Resulting sunset behavior: while chargers are actively charging near high SOC,
the allocator can still taper them to single-digit amps. Once a controller's own
state machine decides input has waned and goes to sleep, the allocator stops
using it as a battery-protection actuator and lifts its stale current limit back
to max so it is ready for the next wakeup.

## Timezone storage audit

The live SQLite store showed mixed timestamp offsets:

- recent `samples` rows were local-offset text such as `2026-06-18T08:36...-04:00`
- recent `events` rows were UTC text such as `2026-06-18T12:32...+00:00`

The cause was not a clock problem; it was inconsistent serialization. Metric
sample generation converted snapshot/device timestamps with local
`astimezone()`, while allocation events kept the UTC supervisor timestamp.

Refactor direction:

- Store all durable `captured_at` values as aware UTC ISO 8601 text.
- Parse legacy local-offset rows as instants for read paths.
- Keep display/local-day semantics at the edge: midnight SOC/load baselines use
  a site-local midnight window converted to UTC for comparison.
- Export batches group by UTC capture date using SQLite `date(captured_at)`,
  which handles both legacy local-offset rows and new UTC rows.

No in-place migration was done. The code now writes UTC rows going forward while
remaining compatible with the older local-offset sample rows already in the
store.

## Charge allocation knee gate and whole-amp writes

After the morning allocator fixes, policy was tightened again:

- `ChargeCeiling` is now the single policy point for charge budget and hard
  stops. It resolves one net charge allowance: `None` means release controller
  limits, positive amps means constrain to that budget, and `0 A` means hard
  stop.
- The resolver should not turn on budget apportionment until the BMS itself
  signals the knee by dropping CCL below the normal 200 A baseline.
- While CCL remains at 200 A, controller limits release to max.
- Once CCL drops below 200 A, the net-charge allowance is now 50% of the BMS
  advertised CCL instead of the earlier guessed SOC/voltage policy.
- Allocation targets are quantized to whole amps before logging/writing.
  Sub-amp changes are skipped by the write deadband to avoid fractional churn on
  controller settings, especially the EPEver register.
- A follow-up stabilizer holds non-emergency live targets inside a 5 A band
  around the current controller setting and snaps larger moves to 5 A buckets.
  Real stops and feedback clamps bypass the smoothing.
- During deploy validation, max-cell voltage was observed bobbling around the
  3.55 V hard stop and toggling the EPEver coil. Cell-safety stops now latch in
  `ChargeCeiling` so the one-budget model has recovery hysteresis.
- The initial 3.55/3.50 pair proved too conservative for live behavior: cells
  were well balanced and SOC was still around 94%. The local guardrail was moved
  to a true safety role: max-cell hard stop at 3.62 V, recovery/upper-zone
  threshold at 3.55 V, and cell-delta stop at 150 mV in that upper zone.

Charge-disable and CCL-zero remain immediate stop conditions.
