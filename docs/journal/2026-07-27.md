# 2026-07-27

## Kindle KUAL display white after the Pi address changed

The Kindle Touch's **Supervisor Display** KUAL entry opened a completely white
WebLaunch window. The server side was healthy: `offgrid-supervisor` and nginx
were active, and both `/` and `/kindle` returned HTTP 200 with the complete
Kindle page. Nginx saw no request from the Kindle, placing the failure before
the HTTP server.

Inspection over USB found the launcher configuration at
`/mnt/us/extensions/WebLaunch/settings.js` hard-coded to:

```text
http://192.168.0.200:8080/
```

That was the Pi's former Wi-Fi address. The Pi is now using its wired address,
`192.168.0.203`, with `wlan0` disconnected, so `.200` had no listener. Changing
WebLaunch to `http://192.168.0.203:8080/` restored the display. The extension's
existing `settings.js.orig-backup` retains the original configuration.

Tried replacing the address with `http://blueberry.local:8080/`. The Pi's
Avahi service was active and other LAN hosts resolved `blueberry.local` to
`.203`, but launching WebLaunch produced no nginx request. The Kindle Touch's
2011 Mesquite environment therefore does not provide usable mDNS resolution
for this launcher. The final configuration uses `.203`; keep that address
stable with a router DHCP reservation.

Useful fault split for the next incident:

- A Kindle request plus an HTTP error in nginx points to the display service.
- No Kindle request at all points to WebLaunch configuration, name resolution,
  or Kindle Wi-Fi.

## Post-fix recalibration: the coefficient will not lock in, but two bigger errors surfaced

Question asked: is there enough telemetry since the 2026-07-18 array 0 wiring
fix to lock in the power-balance model? Answer: no — and sample size is not
the reason. Nine days produced 314 usable uncurtailed bins, more than the 261
that built the original model (array 1's absence removed most curtailment).
The problem is that the estimate is not reproducible. Full write-up in
[power-budget.md](../power-budget.md); this entry records the investigation.

### The 8/7 projection did not confirm

Measured output rose ~40% versus the predicted 14%. Part of that is plausibly
real — an MPPT facing the two local maxima of a 4s ∥ 3s array can settle on
the wrong one, so the fault likely cost more than the idealized 7/8 — but the
windows disagree by more than the fault explains:

| Basis | June (×8/7 for fault) | July (corrected) |
|---|---|---|
| POA, temp-normalized | 1.60 (67% of nameplate) | 2.01 (84%) |
| Clear-sky bins, GHI | 1.33 | 1.86 |
| Sun ≤20°, GHI | 1.18 (R² 0.00) | 0.90 (R² 0.40) |

84% of nameplate is above what this hardware plausibly delivers, so the July
end is likely biased high by selection (uncurtailed bins skew to cool-panel
mornings). Root cause of the instability: the regression's independent
variable is *modeled* irradiance — Open-Meteo GHI, hourly, ~1 km grid, polled
every 30 min — which cannot track real cloud transients at this site. Best fit
achieved was R² 0.56.

Ruled out along the way: weather-feed gaps (48 samples/day at 30-min cadence,
one 103-min gap in nine days); charge-allocator throttling of the Classic
(0.9% of June bins near limit, 0% in July); and array-geometry misfit as the
sole cause (POA reconstruction lifts R² only 0.44 → 0.56).

### Error 1: array 0 was modeled as GHI-proportional but is 45° south

Array 0's geometry was undocumented and is now recorded: **45° tilt, 180°
azimuth, 30 ft above grade**. Modeling a tilted array against horizontal
irradiance is a large seasonal error, because POA(45°S)/GHI runs 0.93 in July
and 1.86 in December — so a summer-fitted GHI coefficient **understates
December output by ~2×**. The model is now on a POA basis for both arrays.
This is geometry rather than a fitted parameter, so it holds regardless of
where the coefficient eventually lands.

Interim array-0-only winter, recomputed (bracket 1.60–2.01):

| Mode | Worst 7-day (median winter) | Generator sessions/winter |
|---|---|---|
| Full occupancy | −25 to −28 kWh | 18–27 |
| No refrigeration (4.38 kWh/day) | −20 to −22 kWh | 12–18 |
| Lean unattended caretaker | **+4.6 to +7.2 kWh** | 0 (min SOC 80–86%) |

Previously these read −32, −12 and +0.8. **Unattended winter 2026–27 on array
0 alone is now comfortable rather than marginal.**

### Error 2: why the pre-meter refrigeration estimate was ~4× too high

The 2.6 kWh/day figure came from subtracting an assumed baseline from the
daily mean, and both halves were wrong. The baseline used the overnight
*minimum* (~95–105 W) — the instantaneous trough when the compressor is off
and nothing else is drawing — instead of the overnight *mean* of ~184 W. Then
the entire remaining gap was attributed to the freezers, when most of it is
ordinary daytime activity.

The meter shows refrigeration nearly **flat at 29–35 W in every hour**, while
total load swings 183 W overnight to 274 W at midday. The diurnal shape
assumed to be compressor duty cycling is human activity. Refrigeration is
14.7% of load, not ~50%. Consequence: **shedding the fridge is no longer a
winter strategy** — it removes ~5 kWh from a 220–280 kWh winter deficit.

Falls out of the same decomposition: overnight load is 184 W, of which ~32 W
is refrigeration and ~93 W is identified always-on gear (Starlink, Magnum
no-load, Pi/comms), leaving **~59 W unidentified and running 24/7** — nearly
twice the refrigeration load, and now the largest available load reduction.

## calibrate_pv.py rewritten

The 2026-07-26 scheduled recalibration produced nothing: the script intersected
array 0 and array 1 bins, so a decommissioned array zeroed the whole run.
Rewritten to fit each array independently, on the POA basis with cell-temp
normalization, reporting the legacy GHI slope alongside for comparability, and
warning when R² indicates the fit cannot support a point estimate.

Fixing that exposed a second latent trap: the EPEver never emits any "Bulk"
word — it folds bulk into "Boost", which the canonical mapping normalizes to
*Absorb* — so filtering it on the Classic's stage vocabulary silently returned
zero bins even in June when array 1 was live. Stage vocabularies are now
per-array. Worth remembering at remount: a zero-bin result reads like "no
data" rather than "wrong filter", so it hides itself.
