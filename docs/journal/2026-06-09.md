# 2026-06-09 — Magnum integration, display regressions, hardening pass

Long session: the SH-U11H RS485 adapter arrived and the Magnum inverter
went from undocumented to live telemetry on every display surface, with a
write experiment, two production regressions, a senior-style review, and
most of the resulting hardening plan landed the same day.

## Magnum RS-485

- First read worked immediately after wiring the breakout (pins 6/3 → A/B,
  termination jumpers left open — Pi is a mid-bus tap).
- `magnum-pi`'s CycleTracker misidentifies inverter vs remote packets when
  joining the bus mid-cycle (remote byte 10 is non-zero, so it gets
  fingerprinted as the inverter). Produced spectacular garbage: 2573.7V,
  137°C. Our `MagnumClient` identifies the inverter packet by model byte
  (0x73 = MS4448PAE at position 14) instead; the captured hex became the
  regression fixture in `tests/test_magnum.py`.
- Wire voltage encoding confirmed: 12V-nominal × 10 per byte → 0.4V
  resolution at 48V. The ME-RC50's front panel moves setpoints in the same
  0.4V steps (finitor verified on the panel), confirming one wire count per
  press.
- Write experiment: injected a remote packet restoring float 54.4 → 54.8V.
  The inverter accepted it for one bus cycle, then the ME-RC50's ~100ms
  retransmission overwrote it. One-shot writes cannot hold against a live
  remote → decision [0002](../decisions/0002-magnum-remote-takeover.md):
  provisionally remove the ME-RC50 and have the Pi own the remote slot,
  validated first by display parity. Findings detailed in
  [magnum-inverter-interface.md](../research/magnum-inverter-interface.md).
- Inverter/Charger display group added across web, terminal, and API
  surfaces as the first validation step.

## Two display regressions, same root cause

Frequent supervisor restarts turned rare race windows into certainties;
both fixes are documented in
[display-services.md](../subsystems/display-services.md):

- Kindle died at 19:25: it was bookmarked straight to :8080, bypassing the
  nginx retry page entirely — that protection had never applied to it.
  Fixed by moving the supervisor to 8081 and pointing nginx at both 80 and
  8080.
- Desktop console window closed permanently on service restart (`exec tmux
  attach` died with the session). Fixed with a re-attach loop; the console
  service is now `BindsTo` the supervisor.

## Test suite philosophy shift

Pruned ~⅓ of the suite: CSS/markup/column-spacing assertions out, behavior
and degraded-state rendering kept, load math moved to `test_load.py`
asserting on functions instead of HTML. `snapshot_helpers.py` factories
mean a new SupervisorSnapshot field costs one line, not 28 edits (measured
the hard way when `magnum` was added). Policy in `tests/README.md`. Load
estimation moved from `web_display.py` to `load.py` — domain logic below
the API layer.

## Review and hardening (engineering-plan.md)

A lifecycle review concluded the structure is sound but the risks were
operational. Items 1–5 landed same-day: single `deploy.sh` (the
restart-on-file-change watcher was retired — it was restarting the
supervisor on every rsync'd file, the proximate cause of the Kindle death),
truthful dependency manifest, magnum decode tests, `/dev/magnum-rs485`
udev symlink, CI. CI immediately caught a real bug: three load tests were
timezone-dependent (hours-since-local-midnight), green in Eastern, red on
UTC runners. Pinned `TZ=America/Toronto` in the test module.

## Per-device actor threads (item 6 phase 1)

finitor's call: one thread per device owning *all* I/O for that device, writes
included — not just reader threads with a lock on the side. `PollingReader`
in `readers.py`: poll loop plus command queue on one thread, so reads and
writes can never race a shared connection; the charger taper write routes
through the classic actor via `Supervisor.write_classic_charge_settings`.
Snapshot composition went from worst-case ~10s of serialized device I/O to
~4ms cache reads. Staleness is explicit: last-good values older than 4×
the interval raise WARNING conditions on every display. Phase 2 (persistent
Magnum listener, which is also where the remote-takeover transmit loop must
live) is specced in the plan.
