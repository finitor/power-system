# 2026-06-15b — sqlite3 operator access and boot-card runbook cleanup

## sqlite3 CLI access for the operator

The operator account had been added to the `offgrid` group (the owner of
`/srv/telemetry/data/`) but sqlite3 was still failing with "attempt to write a
readonly database". Root cause: the data directory is `drwxr-xr-x` (group
`r-x`, not `rwx`), so SQLite cannot create its lock file there even with group
membership.

Workaround for the immediate session: open the database read-only so no lock
file is needed:

```sh
sqlite3 'file:/srv/telemetry/data/metrics.sqlite?mode=ro'
```

Permanent fix added to `scripts/install-pi.sh`:

```sh
sudo chmod g+w /srv/telemetry/data
sudo usermod -aG offgrid "$USER"
```

`sqlite3` itself was also missing from the `apt-get install` list; added.
Note: `usermod` only takes effect in a new login session — log out and back in
(or start a fresh SSH session and tmux) after `install-pi.sh`.

## Boot-card runbook: procedure gaps fixed ahead of 64 GB card swap

Reviewing the procedure for an imminent repeat (swapping back to the original
64 GB Samsung card) surfaced several gaps:

**SSH chicken-and-egg fixed.** The old procedure cloned the repo (via SSH) in
step 4 before restoring `~/.ssh` in step 6. Fixed by reordering: copy archive
first, extract SSH keys from the archive, then clone. The archive stores keys
at `home/offgrid-user/.ssh/`; extraction command:

```sh
BUNDLE="$(tar -tzf "${ARCHIVE}" | head -1 | cut -d/ -f1)"
tar -xzf "${ARCHIVE}" --strip-components=3 -C "${HOME}" \
    "${BUNDLE}/home/offgrid-user/.ssh"
chmod 700 "${HOME}/.ssh" && find "${HOME}/.ssh" -type f -exec chmod 600 {} \;
```

**Fresh backup step added.** Procedure now opens with "take a fresh backup
from the running Pi" before touching anything, so the archive used throughout
reflects the current system state rather than the June 2026 backup.

**Hardcoded archive filename removed.** Step 6 referenced
`offgrid-blueberry-20260612T120203Z.tar.gz` by name; replaced with
`<archive>` placeholder.

**Re-login step added after `install-pi.sh`.** The `usermod` in install-pi.sh
only takes effect in a new session; the procedure now says so explicitly.

**Stale "already complete" note removed.** The June build had left a note that
"preparation steps 1-3 are already complete as of 2026-06-12" — wrong for any
future build.

**Card target updated.** The 64 GB Samsung card is the next build target;
128 GB bumped to "future upgrade."

**Open Questions pruned.** Closed the `/srv/telemetry`-on-SSD question
(answered: external SSD) and the desktop question (answered: no desktop needed
on Lite). Kept the OS image pinning question and the CLI authentication question.
