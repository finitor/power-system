# 2026-06-21 — Fighting the Kindle Touch's 2011 browser

A long arc (spanning 2026-06-20→21) trying to make the Kindle wall display behave:
pin a footer, extend the tap zones, and stop e-ink ghosting. Most of it was
discovering, the hard way, exactly what the Kindle Touch's 2011 WebKit
"Experimental Browser" does and doesn't honor. Recording that here because the
catalogue of quirks is the part that can't be reconstructed from the diffs.

## What this browser honors / ignores (the hard-won table)

| CSS / API | Behavior on this panel |
|---|---|
| `min-height` / `height` on the page box | **Ignored** (both `display:table` and block) — box collapses to content height |
| `height` on a `position:fixed` element | **Ignored** too |
| `position:fixed; bottom:0` | Anchors to the **content box**, not the viewport — falls short on short pages |
| `position:fixed` top/left, `%` width | **Works** (the page-turn strips position fine) |
| Tall fixed elements | **Count toward document scroll length** here (overshoot ⇒ scrollbar) |
| `100vh` / viewport units | Unreliable |
| `documentElement.clientHeight` | Stable ~700, but **under-reports** the visible area |
| `window.innerHeight` | The true visible height **but unstable** — read 704 / 723 / 748 across refreshes |
| `overflow:hidden` on html/body | Clips real content; did **not** stop the fixed-overshoot scrollbar |
| **`padding`** | **Honored** — the one reliable way to size a box |
| In-place `innerHTML` swap (our refresher) | Never triggers a full e-ink waveform ⇒ ghosting accumulates |

## The footer saga (2026-06-20)

Goal: pin the nav footer to the physical screen bottom. Four mechanisms, all
defeated by the table above:

1. CSS sticky-footer via `display:table` + `min-height` — min-height ignored on
   tables, page collapsed to content, footer floated.
2. Block `min-height` + `position:absolute; bottom:0` — min-height ignored on
   blocks too; absolute anchored to the content box.
3. JS-computed absolute `top` from `clientHeight` — placed it relative to the
   wrong (content-height) box; shoved it up into the content.
4. In-flow `padding`-sized spacer — padding *worked*, but in-flow it extended the
   document, pushing content below the fold and adding a scrollbar.

Conclusion: there is no reliable way to bottom-pin on this browser. Gave up on the
footer button entirely and switched to **plaintext margin hints** ("MORE >" right,
"< BACK" left) that point at the existing invisible page-turn tap zones. No
positioning required; problem dissolved instead of solved.

## The ghosting / flash saga (2026-06-21)

The in-place XHR refresh (which we use deliberately, so a server outage can't
strand the display on a native error page) never triggers a full e-ink refresh,
so grey ghosting builds in the changing areas. Added a periodic full-screen
**black→white flash** to force a full waveform.

Getting it to cover the screen without side effects was the same fight:

- Sized to `clientHeight` (700): clean, no scroll, but left a strip at the bottom
  uncovered (the real visible height is ~748).
- Overshot to cover it: covered fully **but added a scrollbar** (fixed elements
  count toward scroll here), and the scrollbar persisted after the overlay was
  removed.
- `overflow:hidden` to kill the scroll: **clipped real content** ("none" rendered
  half-height on the long page) and didn't even stop the flash's scrollbar.

Settled on: flash sized to `clientHeight`, `position:fixed`, no overshoot — it
covers the **changing content area, which is where ghosting actually
accumulates**; the static bottom strip never updates, so it needs no flash. Every
15 min. The on-panel debug readout (`oh=1100 ch=700 ih=748→704`) is what revealed
`innerHeight`'s instability and that padding was fully honored (overlay really was
1100 tall) — i.e. the scrollbar was overshoot, not a paint failure.

Tap zones: `padding-bottom` (honored) carries them most of the way down; the
unstable viewport + fixed-extends-scroll means full bottom reach isn't possible
without the scrollbar returning, so I chose no-scrollbar over the last ~40 px.

Two smaller wins that did stick:
- **Removed the grey `#ccc` cell-divider borders** — they were the worst ghosting
  offenders (persistent light lines). Bold first-column labels carry the rows now.
- **Folded errors into Status Conditions** — a Magnum read error showing next to a
  "none" condition was contradictory and low-density, pushing the nav hint below
  the fold.

## Meta-lesson

The correct fix is to stop using a 2011 browser, not to keep out-quirking it. All
the workarounds are quarantined in `web_display.py`'s Kindle renderers and would
be deleted wholesale on a hardware upgrade. Wrote up the options in
[research/eink-wall-display-upgrade.md](../research/eink-wall-display-upgrade.md):
the short version is that Kindle/Kobo are locked to weak browsers regardless of
generation, and the path to a compliant browser is an Android e-ink device
(Boox / Meebook / Hisense e-ink phone) running a kiosk browser — a near drop-in
given the dashboard is already server-rendered HTML.
