# 2026-07-30

## Recalibration on 12 days: the coefficient is drifting, not converging

Reran `calibrate_pv.py` with three more days of post-wiring-fix telemetry
(12 days total since 2026-07-18). The array 0 coefficient moved down, and the
marginal days moved it hardest:

| Window | Bins | Coefficient (W per W/m² POA at 25 °C) | % of nameplate |
|---|---|---|---|
| 2026-07-19 .. 07-27 | 308 | 2.01 | 84% |
| 2026-07-19 .. 07-30 | 373 | **1.90** | 79% |
| 2026-07-28 .. 07-30 (marginal) | 65 | 1.56 | 65% |

The three new days alone read 1.56 — essentially the June figure of 1.60 once
that window is scaled for the wiring fault. So the running estimate is
drifting toward the *low* end of the 1.60–2.01 bracket as the sample
broadens, rather than settling on the high end where nine days had put it.

This is the sample-composition dependence documented on 2026-07-27, now
visible in real time: each window is internally consistent, R² sits around
0.5, and the windows disagree with each other. The bracket was kept as the
model's input; 1.90 is quoted only as the current midpoint. Nothing here
changes any scenario conclusion — the winter verdicts hold across the whole
bracket — but it is direct evidence that waiting for more summer data will
not produce a point estimate. The fix remains a measured irradiance reference
on site, or winter itself.

## annual_model.py was still GHI-proportional

Found while updating the numbers: `scripts/annual_model.py` had never been
migrated to the plane-of-array basis adopted on 2026-07-27. The doc described
one method and the committed script implemented the superseded one, so
anyone running it would have reproduced exactly the ~2× December
understatement the reformulation exists to correct. The scenario numbers in
the doc were right — they were computed by hand during the reformulation —
but they were not reproducible from the repo, which is arguably worse than
being wrong in an obvious way.

Rewritten to:

- model `PV = k × POA(45° S) × temperature_factor`, matching the documented
  method and the calibration script's basis;
- fetch and cache its own 10-year irradiance series (with a `curl` fallback,
  because the python.org macOS build has no usable CA bundle) instead of
  requiring hand-run `curl` commands from a docstring;
- take the coefficient as a repeatable `--k` bracket rather than a module
  constant, so runs print the spread instead of hiding it in a mean;
- model the post-remount system behind `--array1`.

Verified by reproducing the hand-computed scenario numbers exactly at both
bracket ends (−27.8 / −22.4 / +4.6 at k=1.60; −25.2 / −19.8 / +7.2 at
k=2.01). At the 1.90 midpoint the interim array-0-only winter reads −26.0
full occupancy, −20.6 no-refrigeration, **+6.4 kWh** lean caretaker, with an
83% SOC floor and no empty days across nine winters.

Lesson worth keeping: when a model's method changes, the script that
implements it is part of the documentation. A doc that describes a method its
own tooling no longer performs will mislead the next person more effectively
than a stale number would, because the tooling looks authoritative.
