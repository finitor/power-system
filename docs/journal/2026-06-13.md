# 2026-06-13 — 64-bit dry-run card prep

## Backup completeness before salvaged-card rehearsal

A 32 GB microSD salvaged from another Pi is acceptable for a 64-bit migration
dry run: the current root filesystem uses about 7.3 GB, and `/srv/telemetry`
is on the external Samsung SSD 840 EVO rather than the boot card. It is not
the desired final medium, but it is enough to rehearse the image, restore, and
health-check path while leaving the current 64 GB Samsung boot card untouched
as physical rollback.

Tightened the migration backup/restore coverage before doing the dry run:

- Back up `/etc/fstab`, `/etc/hostname`, `/etc/hosts`, relevant cloud-init host
  config/template files, sudoers snippets, local sshd config, NetworkManager,
  systemd-networkd, wpa_supplicant, and `/boot/firmware/{config,cmdline}.txt`.
- Restore keeps the full old `fstab`, `config.txt`, `cmdline.txt`, and
  sudoers snippets only as reference files on the new image. It does **not**
  overwrite the fresh image's boot/root fstab or cmdline, because those carry
  card-specific root identity; it also does not automatically restore temporary
  privilege files.
- Restore extracts just the `/srv/telemetry` line from the old fstab and
  appends it if the new image does not already have that mount. Current live
  line is the external SSD UUID mounted at `/srv/telemetry` with
  `nofail,x-systemd.device-timeout=10`.

Next step is to deploy these backup changes to the live 32-bit Pi, create a
fresh migration backup, verify that the archive contains the new completeness
items, and only then flash the 32 GB dry-run card.

## TTY console autologin follow-up

After the first 64-bit boot validation, the physical console still stopped at
the stock getty prompt instead of logging the operator in and opening the composed
tmux console. Root cause: the console scripts and `.profile` guard were
restored, but the fresh image never received the `getty@tty1` autologin
override as tracked deploy state.

Fixed `scripts/deploy.sh` to install a tracked
`getty@tty1.service.d/offgrid-autologin.conf` override and to append the
`.profile` guard idempotently. Future rebuilds should get the tty1 console
behavior from deploy instead of a manual `systemctl edit`.

## Operator sudoers follow-up

The fresh-image rebuild path preserved `/etc/sudoers.d` only as reference,
which was too conservative for the known operator policy: deploy and the tty
font hotkeys assume non-interactive sudo. Added a tracked sudoers template that
deploy validates with `visudo -cf` and installs as
`/etc/sudoers.d/020_offgrid_operator`.

## Tailscale follow-up

After rebooting the 64-bit card, the physical console came up correctly but
Tailscale was missing from the fresh image. Added install coverage to
`scripts/install-pi.sh` and added `/var/lib/tailscale` plus
`/etc/default/tailscaled` to migration backup/restore coverage so future card
swaps can preserve the Tailscale machine identity when the backup contains it.

Tailscale was installed on the 64-bit card and authenticated. The fresh auth
initially appeared as `blueberry-1` because the old 32-bit card identity still
existed as offline `blueberry`; the new device was renamed back to `blueberry`
in Tailscale after auth.

## Console split follow-up

The first 64-bit tty console boot used the original 121-column display pane,
which was too wide on the current 192-column console geometry and left only
about 70 columns for the operator shell. Reduced the default display pane to
96 columns and made `offgrid-tty-console` reapply the layout whenever the
outer tty tmux session is reused, so the split can be corrected without
waiting for a full reboot.

## Display and control-API work

A block of display-layer work landed across the day — most on the 32-bit card,
with the console-font tail finished on the 64-bit rebuild. (The 192-column
geometry the migration notes above respond to is a downstream effect of the
font decision below.)

**Weather behind a source-agnostic API.** The terminal and Kindle renderers
and the metrics recorder each parsed Open-Meteo's raw shape and re-derived
weather-code text, wind compass, and moon phase — provider knowledge in three
places, plus the terminal renderer importing the web renderer's private
helpers. Added `weather.weather_api_payload`, a normalizer emitting a stable
schema (units in key names; `current`/`hourly[]`/`daily[]`/`astronomy`;
derivations applied once). `/api/v1/weather` emits it; both renderers and the
recorder consume it; Open-Meteo field names now live only in `weather.py`.
Mirrors the existing `snapshot_api_payload` power path. Stored metric names
were kept unchanged so the time-series stays continuous.

**Vendor-agnostic charge controllers.** Renderers hardcoded "Classic"/"Epever"
titles, a fixed two-controller layout, and (Kindle side) read hardware objects
directly. Each controller now carries a `device:{vendor,model}` block plus a
generic `conditions[]` list, separate from its parameters; both renderers
iterate the `solar[]` collection and build the title from `device`, with no
hardcoded vendor, count, or slot number. Swap in a Victron tomorrow, teach
`_solar_api_payload` about it, and both displays render it automatically.
Vendor strings now live only in `_solar_api_payload`.

**Refresh on panel switch (async).** A manual panel switch queues an
out-of-cycle re-poll of the sources. `PollingReader.request_refresh` /
`Supervisor.request_refresh` are fire-and-forget (enqueue `read_now` on the
device's actor thread, return at once), and `/api/v1/snapshot?refresh=1`
triggers it without waiting — a slow or wedged device can never block the
response; fresh values land on the next refresh. The weather panel got the
same treatment (`WeatherService.request_refresh`, background fetch) once we
confirmed the real cost of a forced Open-Meteo fetch is latency, not the
(generous) free-tier rate limit.

**TTY console legibility.**

- Cell `bank|cell` separator changed to `bank-cell`; the pipe read like a "1"
  on the low-res panel (`1|16` looked like `1116`).
- Framebuffer font: the stock 8x16 console font carries only 256 glyphs, so the
  cell-delta Δ (U+0394) and the trend arrows ↑↓ (U+2191/2193) fell back to
  missing-glyph boxes. Settled on `Uni2-TerminusBold` one step up from stock
  (`10x20` cell → 192x54): Uni2 covers the delta and arrows; Bold is heavier
  than plain Terminus, which read spindly on the wall; and TerminusBold is the
  only heavier face that still has a full size ladder (VGA/Fixed are chunkier
  but exist only at 8x16, forfeiting the size hotkeys). The arrows were the
  deciding constraint — replacing just the delta with ASCII would not have
  freed the font. Deltas stay Δ in the web/Kindle HTML (browser fonts,
  unconstrained).
- Runtime size control: `offgrid-console-font {up|down|reset}` steps the
  TerminusBold ladder via `setfont` and persists the index. Bound to root-table
  `F7`/`F8`/`F6` (no prefix — the nested display tmux makes the tmux prefix
  unreliable from the physical keyboard; Apple keyboards also need `Fn` for the
  function row, `hid_apple fnmode`). The renderer footer carries a `Font ↓F7
  ↑F8` reminder.
- The bottom-pinned footer now re-pins the instant the console is resized: a
  `setfont` size change reflows the tty, and a SIGWINCH self-pipe wakeup added
  to the render loop's `select` re-renders immediately rather than leaving the
  footer dangling mid-screen until the next periodic refresh.

All deployed to the live Pi; full unit suite green (202 tests).
