# 2026-07-20

## Read-only SQLite opens can still break WAL ownership

A `mode=ro` Python query of the live metrics database, run as the operator,
created `metrics.sqlite-wal` and `metrics.sqlite-shm` as `tvetter:offgrid` mode
0644. The inherited ACL's group entry was present but its effective mask was
read-only, so the `offgrid` supervisor reported `attempt to write a readonly
database` and switched to the SD fallback. The degraded notifier correctly
alerted after its 120-second debounce. Restoring both sidecars to
`offgrid:offgrid` mode 660 recovered the primary without a restart and merged
2,180 samples plus 5 events from fallback; no telemetry was lost.

This corrects the July 19 conclusion that setgid plus a default group-write ACL
was sufficient. SQLite can narrow the inherited ACL mask according to its file
creation mode. All live-database opens, including read-only queries, must run as
`offgrid`. The query helper now enforces database-owner access, uses `mode=ro`
instead of `immutable=1`, and can create a consistent snapshot for long or
repeated analysis. Diagnostics also run SQLite explicitly as `offgrid` rather
than root.
