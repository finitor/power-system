# 2026-06-20

## Operator nudge controls for charge voltage

Added a first-class way to walk a charge controller's scalar voltage up or down
in small steps and watch the voltage-based taper react near the knee. The
existing scalar-voltage API gained a `delta_v` alternative to the absolute
`voltage_v`: the supervisor reads the controller's current setpoint on the
device's actor thread, adds the delta, re-applies the scalar policy, writes, and
confirms the readback. `scripts/charge-controller-voltage.py --by ±0.1` is the
shell front end.

The supervisor terminal display (`api_terminal_display`) grew a **tune mode**
(`t`) for the same operation without leaving the console. It is deliberately
**staged-commit**: `+`/`-` stage a change shown as `→ target (Δ)`, and nothing is
sent until `Enter`. That builds the confirmation step into the interaction rather
than bolting a modal onto every keystroke. Protections, outermost last: the `t`
arm gate, a per-session budget, idle auto-disarm, and the supervisor-side BMS-CVL
guard as the hard backstop. A cat on the keyboard can't move the system; an
informed operator taps a few keys.

## CCL scaling factor: name, persistence, nudge size

The charge allocator's "take 50% of the BMS CCL near the knee" knob is now an
operator control too — same delta API / script / tune-row treatment. Three
follow-on decisions came out of using it:

- **Naming.** It was briefly "CCL budget fraction", but "budget" already means
  the charge-current limit plus the household-load allowance (`budget_a`), which
  is the more intuitive home for the word. Renamed everywhere to **CCL scaling
  factor** (`bms_ccl_scaling_factor`, `POST /api/v1/control/ccl-scaling-factor`,
  `scripts/ccl-scaling.py`, snapshot `allocation.ccl_scaling_factor`).
- **Persistence.** The first cut was in-memory only, so a deploy/restart wiped
  the operator's setting (observed live — a 60% nudge reverted to 50% after two
  deploys). It now persists to a JSON runtime-state file
  (`/var/lib/offgrid/runtime-state.json`) via a `ChargeCeiling` on-change hook
  and reloads at startup; the env default applies only when the file has no
  value. Deliberately *not* the hand-edited env config — a machine writer there
  would clobber comments and entangle runtime state with boot config.
- **Nudge size.** A 5-point nudge near a 40 A CCL moves each controller by ~2 A,
  which the allocator's 5 A target deadband/quantum correctly swallows (no write
  chatter) — so the operator saw "nothing happened". Kept the deadband; enlarged
  the default tune step to 10 points so a deliberate nudge clears it. The Limit
  line now also shows the live scaling factor (`; scaling 60%`) so a change is
  visible even when the per-controller writes legitimately hold.

This is the first supervisor-side *runtime policy* operators can change live, as
opposed to device-register writes — worth noting because its persistence story
(JSON state file, not EEPROM) is different in kind from the voltage writes.

## EPEver "Production Today" read absurd values

The EPEver's daily-generation register doesn't reset reliably, so "today" is
derived as lifetime-total minus the total logged at local midnight. When that
midnight baseline went missing (pruned in an earlier logging cleanup), the
derivation fell back to the raw register and the console showed ~7.4 kWh — under
constant human scrutiny for days, flagged only as "that looks wrong". The
derivation now suppresses the value when it can't be computed and the display
reads "unavailable, midnight cumulative energy was not logged" (mirroring the
existing midnight-SOC-unavailable handling). The raw register is still recorded
for diagnosis. It should self-heal once the supervisor runs across a local
midnight and records a fresh baseline.

A good argument for unit tests in a display-heavy area: the bad value was on
screen continuously and human eyes still didn't catch *what* or *why*.

## Display test strategy: golden frames

Maintaining line-by-line assertions on rendered frames was a recurring token
sink — a label rename rippled through dozens of `assertIn`s, and the churn was
purely cosmetic. Reconciled the "constant human scrutiny → low test value"
argument with the real risks: the brittle part is *layout*, which humans do
watch; the valuable part is *logic* colocated with rendering (the tune-mode state
machine, the EPEver-unavailable decision, HTML escaping, routing), which a glance
can't verify.

Whole frames (terminal snapshot/weather, Kindle, browser) are now pinned with
golden files in `tests/golden/` (`golden.check_golden`), re-blessed in one
command on an intended restyle. Behavioral assertions stay explicit next to the
golden check. Net: the two terminal frame tests and three HTML frame tests shed
~90 lines of brittle assertions while *increasing* what the golden actually pins.
See [tests/README.md](../../tests/README.md#golden-frames).
